## Текущий интерфейс

Темы: «Светлая» по умолчанию и «Темная». «Студия» переименована,
«Портал» убран; старый выбор автоматически открывается как Светлая.

Roadmap объединяет задачи, календарь, Канбан и Скрам в одном планировщике.
Добавляйте задачи вручную или из Jira, назначайте сроки и исполнителей,
выбирайте нужный вид работы с планом.

- «Доска → Канбан» показывает задачи по статусам, «Доска → Скрам» по спринтам.
  В Скраме перетащите задачу в нужный спринт или выберите его в строке.
  Перенос можно отменить; даты и статус не меняются, изменения не отправляются в Jira.
- Фильтр исполнителей показывает число задач и сортирует от большего к меньшему.
  Числа учитывают остальные фильтры, а не означают оценку загрузки в часах.

- «Данные → Поделиться»: выберите безопасный просмотр, материалы встречи или
  полную копию для редактирования. Полная копия включает внутренние задачи,
  архив и историю; передавайте ее только доверенному получателю.
- В безопасной копии можно установить отдельный пароль: минимум 14 символов
  или четыре слова. Он не сохраняется в настройках, передавайте его отдельно.
  Внутренние задачи и история исключаются независимо от наличия пароля.
- Пакет из четырех защищенных файлов доступен в «Поделиться → Дополнительно».
- «Собрать план» и обучение открывают один маршрут: задачи, проверка данных,
  сроки, сохранение. Дополнительные настройки доступны на шаге проверки.
- В «Встреча» управление набором и форматы раскрываются кнопкой
  «Настройки и экспорт» на любом экране.
- Импорт Jira сначала показывает измененные и спорные строки. Новые задачи
  уже выбраны для добавления. «Полный список» показывает все строки; смена
  вида не сбрасывает галочки. Итог отдельно сообщает о ранее убранных задачах.
- Для обычной работы нужен один сохраненный рабочий HTML. Обновление программы
  выполняйте с резервной копией и проверкой сохранности плана и истории.

[История версий](RELEASE_NOTES.md) вынесена отдельно. Здесь описана работа
с текущей версией. Снимки каталога и ролик показывают ее на вымышленных данных.

## Быстрые маршруты

| Что нужно сделать | Где открыть |
| --- | --- |
| Работать с задачами и датами | «Список» или «Доска» |
| Разобрать задачи по статусам | «Доска» → «Канбан» |
| Распределить задачи по спринтам | «Доска» → «Скрам» |
| Проверить срок | «Сроки» → «Прогноз» |
| Посмотреть готовность и перегруз | «Сроки» → «Сводка» |
| Найти ошибки исходных данных | «Сроки» → «Проверить данные» |
| Сравнить варианты | В прогнозе «Сравнить сценарий» или «Другие варианты решения» |
| Подготовить встречу | «Встреча» → «Статус», «План» или «Итоги периода» |
| Выгрузить XLSX, PNG или резерв времени | «Встреча» → «Другие форматы и выгрузка» |
| Сохранить работу | «Данные» → «Сохранение и восстановление» → «Сохранить рабочий файл» |
| Подключить дополнительные возможности | «Инструменты» → «Подключить функции» |

Материалы собраны во вкладке «Встреча». Вкладка «План» внутри нее готовит выбранный набор задач: ее PDF и HTML не
равны действию «Обзор всего плана (PDF)» в других форматах. Перед передачей
проверьте состав, внутренние задачи и шапку. «Скачать для просмотра» использует
отдельные правила исключения внутренних данных; обычная презентация их не заменяет.

В переносимом HTML основная кнопка сохраняет рабочий файл, а «Скачать копию»
создает отдельный файл. JSON, привязки, автокопии и технические статусы находятся
в «Дополнительные действия». Точки возврата служат для восстановления, а
план/факт остается отдельным инструментом сравнения сроков.

В новом пустом проекте включена основа планирования. Деньги, метрики и RICE,
свои поля, цели и ручной реестр рисков подключаются по необходимости. Скрытие
функции не удаляет ее данные. У старых файлов и импортируемых планов прежние
настройки сохраняются. Команда, оценки и зависимости остаются включены,
поскольку нужны для прогноза сроков.

О сохранении и переносе плана: [Рабочий HTML: перенос одним файлом](#рабочий-html-перенос-одним-файлом).

## 1. Что это

Roadmap, локальный планировщик в одном HTML-файле. Для работы с планом не нужны отдельный сервер и регистрация. В приложении есть задачи со сроками и статусами, иерархия секций, зависимости, вехи, релизы, прогноз и отчеты.

Рабочий HTML сохраняет приложение, план, архив задач и точки возврата вместе. Браузерный черновик помогает продолжить работу, но не заменяет файл; JSON остается дополнительным форматом обмена. История и доступ к выбранным файлам могут использовать IndexedDB. Обычная работа с планом не отправляет его на сервер. Переходы по внешним ссылкам и обмен с Jira используют сеть; прямое подключение и автообновление Jira включаются пользователем отдельно. Импорт проверяет структуру данных, но это не заменяет резервные копии. Облачной синхронизации и одновременного редактирования нет.

## 2. Быстрый старт

Для работы со своим планом получите у владельца локальный или полный комплект
v17.1. Они остаются локально и не публикуются в GitHub. Для публичного релиза
предназначены только `Roadmap-v17.1-public.zip` и
`Roadmap-v17.1-public.zip.sha256`. Публичный ZIP содержит демонстрацию,
а не рабочий `roadmap.html`. Результаты проверки файлов приведены
в `QUALITY_REPORT.md` и `validation.json` комплекта. Публикация в GitHub
проверяется отдельно после загрузки.

1. Откройте рабочий HTML двойным кликом или перетащите в браузер. Если у вас защищенная копия, введите свой PIN. Chrome и Edge поддерживают прямую запись в выбранный файл; в других совместимых браузерах сохраните новую копию. Сжатым HTML нужны CompressionStream и DecompressionStream.
2. На стартовом окне выберите, с чего начать:
   - **«Продолжить с файлом: …»** — открыть ранее подключённый файл автосохранения, если он доступен.
   - **«Импортировать данные»** — раскрыть выбор способа загрузки: **«JSON + автосохранение»**, **«Импорт JSON-копии»** или **«Импорт из Jira»**. Первый вариант подключает выбранный файл для дальнейшего сохранения в Chrome/Edge; импорт копии не подключает исходный файл к автосохранению.
   - **«Открыть готовый пример»** — посмотреть встроенный демонстрационный план. Его копия сдвигается к текущей неделе, сохраняя длительности и дни недели. Таймлайн показывает весь пример; рабочие данные не меняются, правки демо не сохраняются.
   - **«Создать пустой план»** — начать с нуля после подтверждения очистки текущего проекта.
   - **Недавние файлы:** внизу показываются до трёх последних файлов. Браузер может запросить подтверждение доступа при открытии.
3. Стартовое окно закрывается крестиком или кликом по фону. Вернуться к нему можно по логотипу. Кнопка **«i» («О проекте»)** в правом верхнем углу стартового окна открывает справку **«Как работать с планом»**. Внизу стартового окна находятся **«Первый рабочий план»** и **«Обучающие сценарии»**.

В справке «Как работать с планом» доступны обучение, описание текущей версии
и история изменений. В нижнем блоке «Подсказки по работе» собраны загрузка Jira,
сохранение и отправка, примеры JQL и клавиши. Три темы выбираются в
Настройки → Интерфейс. Для первого запуска включена Студия; явно сохраненная
тема остается прежней. Печать и изображения для отчетов остаются светлыми.

### Первое знакомство и обучение

На стартовом экране кнопка **«Первый рабочий план»** открывает четыре шага:
начать со своих задач, проверить финальные статусы, разобраться со сроками и
сохранить результат. Это обычная панель над планом, а не перекрывающий экран тур.
**«Позже»** сворачивает её в кнопку продолжения; обучение не обязательно для работы.

Кнопка **«Обучающие сценарии»** предлагает три коротких маршрута:
«Подготовить план», «Проверить сроки» и «Подготовить показ».
Они открывают существующие разделы Roadmap; импорт, изменения и выгрузку
по-прежнему подтверждает пользователь. Переход «Дальше» сам по себе не означает
выполнение действия.

**«Учебный пример ↗»** открывается в отдельной изолированной вкладке.
Рабочий план, его несохранённые изменения, настройки и история остаются в исходной
вкладке. В примере нельзя подключить рабочий файл или записать в него изменения.
Закройте учебную вкладку, чтобы вернуться к своему проекту.

Для переноса плана сохраните рабочий HTML через «Данные → Сохранение и
восстановление». Отдельный учебный шаг сохранения пока проверяет дополнительную
JSON-копию: подключенный файл с подтвержденной записью либо скачанную копию.
После скачивания JSON проверьте его в загрузках и подтвердите это в обучении.
Последующие изменения плана снимают отметку учебного шага. Прогресс обучения
хранится отдельно от снимка проекта; эта отметка не заменяет сохранение HTML.

## 3. Главный экран

- Шапка: логотип открывает стартовое окно, название проекта можно изменить. У названия видны PO, текущая дата и версия. Справа находятся поиск, «Добавить», «Инструменты», «Данные», иконки сохранения, настроек и Архива.
- На компьютере и телефоне четыре основные вкладки: «Список», «Доска», «Сроки», «Встреча». На телефоне они находятся в нижней панели. В «Доске» доступны «Канбан» и «Скрам», в «Сроках» доступны «Прогноз» и «Сводка», во «Встрече» доступны «Статус», «План» и «Итоги периода».
- Меню «Инструменты» в правой части шапки: «Собрать план», «Команда», «Справочники», изменения Jira и «Подключить функции». В «Дополнительных инструментах» находятся «Стратегия», «Деньги» и прежние профили «Планирование / Руководство». Проверки данных и прогноз открываются в «Сроках и рисках»; «Уложиться в дату», «Проверить нехватку команды» и «Проверить эпики Jira» находятся в «Сроки → Прогноз → Другие варианты решения». Дополнительные функции нового пустого проекта выключены; старые настройки сохраняются.
- «Инструменты → Сводка плана» открывает готовность, число задач в работе, просрочку и ближайшие даты. Архив открывается отдельной иконкой в шапке. На телефоне меню инструментов подписано «Еще».
- Все материалы находятся во «Встрече». Для PDF, изображения, текста для чата и таблицы XLSX раскройте «Другие форматы и выгрузка».
- В Настройках четыре раздела: «Основное», «Интерфейс», «Функции» и «Справочники». В «Основном» меняются название, РО, автор, адрес Jira и валюта. Темы: Светлая по умолчанию и Темная. Старый выбор Портала открывает Светлую. Тема не меняет данные плана.
- В «Функциях» включаются Деньги, Оценки, Команда и загрузка, Метрики и RICE, Свои поля, Jira, Зависимости, Цели и инициативы, Риски. Выключение скрывает связанные элементы, но сохраняет их данные. Некоторые функции влияют и на расчеты: например, выключенные зависимости не участвуют в переносах и критическом пути. Настройки функций сохраняются с проектом. Профили вида позволяют сохранить набор фильтров, масштаб, режим и функции.
- Кнопка «Статусы · Все» открывает статусы с количеством задач и быстрые срезы. Можно выбрать несколько статусов, включая импортированные. «Все статусы» снимает только выбор статусов. Каждый выбранный фильтр появляется под панелью и снимается своей кнопкой с крестиком. Финальные статусы настраиваются отдельно, см. раздел 8.
- Кнопка «Фильтры» открывает выбор Jira-проектов, исполнителей, меток, компонентов, релизов и своих полей. «Горящее» оставляет активные просроченные задачи, задачи со сроком в ближайшие семь дней и блокеры; «Мои задачи» сверяет исполнителя с именем автора из Настроек. Доступны наборы фильтров и сброс. Активные фильтры влияют на Список, Доску, Сводку и прогноз.
- В «Списке» слева находятся задачи, справа календарная диаграмма. Рабочий файл открывается на текущей неделе. Масштабы: «По дням», «Неделя», «Месяц»; «Сегодня» перемещает шкалу к текущей дате, стрелки прокручивают даты. На телефоне «Список / Таймлайн» переключает области. В остальных вкладках календарные кнопки скрыты.
- «Фильтры → Все типы задач» позволяет выбрать инициативы, эпики, стори, задачи, подзадачи, дефекты, вехи и пользовательские типы Jira. При выборе уровня иерархии остаются его задачи и вложенные разделы; родители сохраняются как контекст. Можно выбрать несколько типов. Выбор сочетается со статусами и другими фильтрами, сохраняется при перезагрузке и входит в набор фильтров. «Все типы задач» снимает только этот фильтр; общий сброс снимает все фильтры.
- Задачи в работе, на ревью, тестировании и последующих активных статусах остаются на Ганте. Их полосы продолжаются до сегодняшней даты; будущий плановый конец не сокращается. Если плановые даты заданы не полностью, начало берется из истории рабочего перехода, а при отсутствии такой истории используется заданная дата начала. Для завершенных задач и задач на паузе история заканчивается последним событием. Без известного начала период не придумывается. Полоса без полного плана открывает карточку по нажатию, но не перетаскивается и не растягивается. Это только отображение: плановые даты, расчеты прогноза и исторические периоды презентации не меняются.
- При вертикальной прокрутке Ганта сверху остаются шапка приложения, статусы, управление видом, календарь и кнопки «Задачи, сроки, критерии». Закрепленные кнопки управляют плотностью, сворачиванием, выбором задач, сортировкой и добавлением секции. На узком экране они доступны в режиме «Список», календарь в режиме «Таймлайн». Даты синхронизированы с горизонтальной прокруткой. В других видах, при экспорте изображения и печати панель возвращается на исходное место.
- При высоте окна до 600 px верхняя карточка проекта прокручивается, оставляя место задачам. Статусы, календарь и кнопки задач остаются закреплены. Переход к элементу учитывает высоту закрепленной области.
- Меню над списком управляет детализацией и сортировкой. На широком экране разделитель между списком и диаграммой можно перетаскивать; двойной клик возвращает исходную ширину. «Связи» открывает список зависимостей, соседняя кнопка управляет показом и формой линий. Еще одна кнопка включает отсутствия команды на шкале.

## 4. Спринты на таймлайне

Спринты живут прямо на основном таймлайне: под шапкой дат , полоса с плашками спринтов (имя и даты, текущий подсвечен). По плашке видно, попадает ли задача в свое окно спринта; задача, вылезшая за окно, помечается значком-календариком.

Настройки раскладки и спринтов открываются кликом по плашке спринта. В них задаются имена, даты, длина и параметры занятости. Эти данные использует «Прогноз срока» вместе с оценками задач, рабочими днями и отсутствиями команды.

Отдельный вид «Спринты» убран: его прогнозную работу выполняет «Прогноз срока», а окна спринтов видны на основном таймлайне.

- Спринты и все настройки сохраняются вместе с файлом проекта.

## 5. Работа с задачами

- На узком экране длинные названия и метаданные переносятся, а команды строки располагаются отдельно. На широком экране дополнительные команды открываются кнопкой с тремя точками: вверх, вниз, перенос в секцию и скрытие. `Esc` закрывает меню и возвращает фокус.
- Добавить: кнопка «Добавить» в шапке открывает новую задачу с выбором секции. Контекстная кнопка добавления в секции сразу выбирает эту секцию; «+» на общей панели списка создает новую секцию.
- Открыть карточку: клик по строке или полоске. В карточке четыре вкладки: «Основное», «Планирование», «Jira и связи», «История». На первой находятся название, секция, статус, исполнитель и даты; оценки, дополнительные параметры, связи и история доступны на соответствующих вкладках.
- В карточке: название, секция, статус, исполнитель, даты, оценки, релиз, зависимости, метки, веха, блокер, метрики, ссылки Jira/Confluence/Figma, заметки, свои поля и история. Состав зависит от видимости полей и включенных функций. Старые значения DoR/DoD сохраняются в данных, но отдельных полей для них в текущей карточке нет.
- Все возможности карточки доступны без переключения режима. В «Настройки → Функции» можно отдельно скрыть описание, исполнителя, приоритет, оценки, стоимость, метрики, RICE/WSJF, свои поля, метки, релиз и инициативу. Там же настраивается видимость владельца, текущей даты, сводки и меток в шапке проекта. Это локальное оформление на устройстве: значения, расчеты и данные проекта не удаляются. Отключенные модули по-прежнему управляются отдельно.
- Даты не обязательны: задачу можно сохранить без старта и окончания или только с одной датой. Если известно начало работы по истории статусов, Гант покажет фактический период; активная работа продолжается до сегодня. Без известного начала полоса не придумывается. Плановые даты при этом не меняются. Вехе дата обязательна.
- Передвинуть/растянуть: тяните полоску по таймлайну (сдвиг дат) или за край (изменение длительности). Зависимые задачи могут сдвигаться следом.
- Зависимости: тяните от одной задачи к другой, чтобы связать «конец , начало». Циклы не допускаются. Кнопка «Связать задачи по датам» расставляет связи автоматически , по датам задач.
- Вехи: задача-ромб без длительности. Отмечается в карточке.
- Блокеры: тег «Блокер» подсвечивает задачу красным и попадает в фильтр-таб «Блокеры».
- Мультивыбор: включите режим выбора, отметьте задачи, примените массовое действие (статус, в секцию, в архив) или дублируйте задачу.
- Свои поля: у задач можно завести собственные поля, включая новый тип «Чекбокс». Суммы числовых полей показываются в шапке секции , удобно следить за итогами по группе задач.

## 6. Секции и эпики

- Секция , группа задач. Эпик из Jira становится секцией вида `Epic: Название [KEY-123]`.
- Вложенность: Эпик → История → Задачи / Баги. Parent и явные связи Hierarchy [Gantt] задают прямого родителя; Epic Link связывает историю с эпиком. Если у задачи есть только Epic Link, она остается отдельно в «Задачах без истории», пока не уточнен родитель. Blocks, Relates, Duplicate и другие связи сохраняют исходные названия и направления, но не назначают папку. Входящие Blocks становятся предшественниками, когда связанная задача есть в плане или архиве.
- Частичная CSV без родительских полей не стирает известную вложенность. Сохраненные ключи родителей восстанавливают папки при повторном открытии JSON. Разные имена контейнера с одним ключом Jira не создают новую пустую папку; самостоятельная история без задач остается допустимым разделом.
- В заголовке секции: процент готовности (доля выполненных задач, дробь готово/всего), статус эпика, управление (поднять/опустить, скрыть, удалить, добавить задачу «+»), цвет.
- Карточка эпика: карандаш на шапке секции открывает карточку. В ней , те же поля, что проверяет «Аудит Epic»: ключ Jira, тип, статус, проект, плановое окончание, WSJF, метрика, описание. Ниже , сводка по задачам секции (сколько готово, сроки, стоимость) и быстрые действия: цвет, дублирование, вложенность, копирование списка задач, удаление. В файле «для просмотра» карточка открывается только для чтения.
- Сворачивание: свернутая секция прячет все вложенное поддерево (подсекции и их задачи), а вехи остаются ромбами на ее полосе , важные даты видны даже в свернутом виде.
- Скрытые секции и задачи уходят в раздел «Скрытые» , для читаемости карты, без удаления.

## 7. Отсечки и релизы

- Отсечка/релиз , вертикальная линия с датой и названием. Создается кнопкой в шапке или автоматически из релизов Jira (Fix Version с датой). Если несколько отсечек попадают на близкие даты, вместо наложенных меток рисуется кружок со счетчиком , по клику открывается список всех меток на эту дату, каждую можно открыть на правку или удалить.
- Любую отсечку можно закрепить в шапке (показ метки рядом с датой).

## 8. Статусы и ресурсы

- Статусы: настраиваемый список. Исходный набор: «В плане», «В работе», «На холде», «Выполнено». Импорт может добавлять «Ревью», «Тестирование», «Готов к релизу» и другие статусы. Цвет статуса используется на полосе задачи.
- Финальные статусы: Настройки → Справочники → Статусы задач. Отметьте «Финальный» у состояний, которые завершают работу в вашем процессе. Они входят в готовность и не считаются просроченными; задачи не переименовываются и не перемещаются в архив. Явный выбор имеет приоритет перед категорией Jira. Без явного выбора учитываются сохраненная категория и группа статуса; для прежнего стандартного `completed` сохраняется правило завершения.
- Разные исходные названия Jira остаются отдельными статусами, даже если относятся к одной группе. Исходные идентификатор и категория сохраняются, когда присутствуют в выгрузке. `Unresolved` или «Не выполнено» не становятся финальными по совпадению части слова. Если категория неизвестна, предпросмотр предупреждает об этом, а не угадывает состояние.
- Доска: столбцы и фильтры включают фактические статусы задач, в том числе импортированные. В настройке «Столбцы» можно скрыть отдельные колонки без удаления задач; счетчик «В скрытых столбцах» показывает, сколько задач осталось вне показа.
- Команда: один пункт меню «Команда» открывает окно с вкладками (люди и роли, загрузка, производственный календарь). Прежние два пункта , «Роли и ресурсы» и «Загрузка команды», они открывают одно окно на нужной вкладке (вкладки переключаются и внутри). Вкладка «Роли и ресурсы» оформлена таблицей с колонками имя, роль, ставка, доступность, отпуска; под именем видны число задач и мини-бар загрузки, отпуска показаны чипом , клик по нему раскрывает редактор периодов. Над таблицей , сводная строка: «N человек, M ролей, средняя ставка». Исполнитель может быть именем (`a.ivanov`), ролью (`РО`) или связкой «роль-имя» (`PO-a.ivanov`); у задачи может быть несколько исполнителей сразу , при сохранении карточки они не теряются, а нагрузка делится между ними. Переименование исполнителя переносит на новое имя его ставку, доступность и отпуска , ничего не нужно вводить заново. Блок «Кто есть кто» группирует людей по ролям. Для строки-роли поле «назначить роль» не показывается.
- Загрузка команды (вкладка «Загрузка»): один экран с переключателем масштаба , День, Неделя, Месяц (отдельного пункта «Загрузка по неделям» больше нет, все собрано здесь).
  - День , тепловая карта: сколько задач у каждого исполнителя идет одновременно по дням (зеленый , одна, желтый , две, красный , три и больше). Над картой есть выбор «Показать»: можно оставить только нужных людей (чипы), «Все» возвращает всех, выбор сохраняется. Кнопка «Выровнять загрузку» предлагает сдвиги пересекающихся задач исполнителя (по одной или все разом). При прокрутке колонка с именами не перекрывается клетками.
  - Неделя и Месяц , таблица: сколько рабочих дней назначено каждому человеку по неделям или месяцам, перегруз подсвечен (зеленый , в норме, желтый , выше нормы, красный , перегруз). Наведите на ячейку , увидите список задач периода. Клик по имени человека в таблице показывает его задачи на диаграмме.
  - Вид «По ролям» стал иерархическим: роль раскрывается до людей в ней, а человек , до своих задач, и у каждого уровня виден итог. Видно загрузку и по роли в целом, и по конкретному человеку, не выходя из одного списка.
- Контроль перегруза: перегруз смотрите в «Загрузке команды» , на вкладках «Неделя» и «Месяц» перегруженные ячейки подсвечены, а клик по имени человека показывает его задачи на диаграмме. Отдельный чип «Перегруз: N» из шапки убран, чтобы шапка оставалась спокойной. Проверить сроки с учетом загрузки помогает «Прогноз срока»: прогноз использует трудоемкость и доступность исполнителей, не изменяя плановые даты.

## 9. Данные: импорт, экспорт, автосохранение

### Рабочий HTML: перенос одним файлом

В «Данные → Сохранение и восстановление» выберите «Сохранить рабочий файл».
Вместе сохраняются приложение, полный план, архив задач и точки возврата
текущего проекта. Откройте этот HTML на другом компьютере, импортируйте Jira
или внесите правки и сохраните HTML снова.

При первом сохранении Chrome/Edge предложит выбрать файл. Можно выбрать
открытый переносимый HTML или новое имя. Если файл изменен в другой вкладке
либо принадлежит другому проекту, приложение остановит замену и предложит
скачать отдельную копию. Не удаляйте исходники до проверки новой копии.

«Скачать копию» работает и без прямого доступа к файлам. Скачивание
не заменяет открытый HTML: на другой компьютер передавайте новую копию
из загрузок. Перед закрытием убедитесь, что она действительно скачалась.

Черновик браузера и файл могут различаться. При повторном открытии приложение
предложит выбрать данные из HTML или черновик, не объединяя их автоматически.
Личный HTML с первым входом предлагает задать и повторить PIN из четырех цифр.
Нажмите «Подготовить защищенную копию», затем «Скачать защищенный HTML».
Проверьте `roadmap-protected.html` в загрузках: для следующих входов и переноса
нужен именно он. Первоначальный HTML и прежний JSON остаются без шифрования.
В защищенной копии PIN сохраняется при обычной записи HTML; браузерный черновик
тоже зашифрован. Открытая история работает в памяти вкладки и включается в
сохраненный HTML. При обновлении программы защита не снимается.
Забытый PIN восстановить нельзя. Четыре цифры можно подобрать, поэтому не
публикуйте личный файл в открытом GitHub. Обычная чистая сборка без экрана PIN
не шифруется автоматически. Отдельные JSON, CSV и отчеты не наследуют PIN.
Для передачи другим людям используйте «Поделиться копией» или «Защищенные копии».

JSON остается дополнительным форматом. Если первый HTML создан из старого
JSON, история прежнего браузера в нем отсутствует: обычный JSON не содержит
все точки возврата. Экспортируйте историю из прежней рабочей вкладки и
импортируйте ее через дополнительные действия окна сохранения, затем сохраните HTML.
Новая реализация не удаляет прежний JSON и историю старого браузера.

### Импорт, экспорт и сохранение

В предпросмотре Jira и в настройке соответствия CSV проверяйте сводку статусов: исходное название, статус в плане, группа, финальность и число строк. Пустой статус в обновляемой строке сохраняет текущее значение. Если прежняя версия уже объединила несколько исходных статусов, нужен повторный импорт исходного файла: восстановить потерянные названия по одному локальному статусу невозможно.

Для папок и связей включайте в запрос задачи вместе с родительскими историями
и эпиками, затем выбирайте CSV со всеми полями. Проверьте Parent / Parent id
и Issue id, Epic Link, входящие и исходящие связи с типами, включая
Hierarchy [Gantt], если она используется. В предпросмотре раздел «Папки и
связи в файле» показывает задачи без истории, отсутствующих и неоднозначных
родителей. Для числового Parent id нужен Issue id родителя в том же файле.
CSV для Jira включает папки отдельными строками, Parent и типизированные связи.
Перед загрузкой в Jira проверьте сопоставление каждого типа связи и родителя;
скачивание из Roadmap само ничего в Jira не меняет. Доступность полей зависит
от настроек и версии Jira. [Правила сопоставления Atlassian](https://support.atlassian.com/jira-software-cloud/docs/mapping-csv-data-to-jira-fields).

Вверху меню «Данные» находятся «Импорт из Jira», «Сохранение и восстановление»
и «Поделиться». Раздел «Дополнительно» раскрывает другие источники, JSON и
совместимость, шифрованный JSON, замок от случайных правок, план/факт и журнал.
Сжатие истории находится в «Дополнительно → JSON и совместимость».
«Сохранение и восстановление» собирает рабочий HTML, точки возврата и
действия с файловыми привязками. Эти дополнительные форматы не заменяют
рабочий файл. Встроенный инструмент «Защищенные копии» доступен через
«Поделиться → Дополнительно»; отдельный HTML-локер открывать не нужно.

В окне «Поделиться» выберите, что получит другой человек: план для просмотра,
материалы встречи или полную копию для редактирования. У каждого варианта
есть описание и отдельная кнопка. Полная копия содержит архив и историю,
а защищенный рабочий HTML сохраняет прежний PIN. Передавайте такую копию
только доверенному получателю. Файлы создаются локально, без автоматической отправки.

Основные возможности:

- Импорт / экспорт Jira: CSV скачивается через вашу сессию в Jira; Roadmap не получает пароль этой сессии. При необходимости Jira сама попросит войти. Прямое подключение настраивается отдельно.
  - Импорт проходит в одном окне за три шага: **выберите задачи → загрузите CSV → проверьте изменения**. На первом шаге укажите адрес Jira и проекты через запятую (например, `WEB, APP`), свой JQL или выберите Jira-ключи из плана. Есть быстрые условия: открытые задачи, текущий спринт, эпики, последние две недели. Нажмите «Открыть задачи в Jira», скачайте там «CSV (все поля)» и на втором шаге нажмите «Выбрать CSV». Если файл уже есть, начните с кнопки «CSV уже скачан». Третий шаг показывает предпросмотр в том же окне: выберите строки и примените изменения. До применения план не меняется; можно вернуться к файлу или закрыть окно. Длинный список ключей открывается несколькими запросами, файлы загружаются по очереди. Адрес и проекты запоминаются. Прямое подключение по токену осталось на первом шаге в раскрываемом блоке и работает, если Jira разрешает запросы из браузера. Профили сопоставления колонок сохраняются вместе с проектом (до 10 профилей).
  - Импорт бережет ваши даты: если вы проставили сроки задачи руками, повторный импорт из Jira их не перетрет. Даты ставятся из Jira только когда они там реально есть, а у закрытых задач проставляется дата закрытия. Так план не сбивается после каждой выгрузки.
  - Экспорт: «Скачать CSV для Jira» готовит файл для мастера External Import. Обновление существующих задач требует корректных ключей Issue key, сопоставления колонок и нужных прав в Jira. Сначала проверьте небольшой набор: скачивание CSV само по себе ничего в Jira не меняет. Кнопка открытия импорта ведет в мастер Jira.
- Загрузить Jira CSV (файл): быстрый путь, если CSV уже скачан. Читает Issue key, Summary, Status, Assignee, Epic Link (или Parent), Fix Version, метки, компоненты, спринты и даты. Эпики становятся секциями. Повторный импорт обновляет задачи по ключу, а не плодит дубли. Многозначные колонки (несколько меток, Fix Version, спринтов) читаются полностью.
- Импорт JSON / Экспорт JSON: дополнительный снимок данных плана для обмена. Он не содержит приложение и точки возврата из браузера. Для переноса всей работы сохраняйте рабочий HTML; перед передачей JSON проверьте внутренние данные.
- CSV для Jira: содержит название задачи в колонке Summary. По умолчанию включает только задачи с Jira-ключом. Параметр «Включить задачи без Jira-ключа как новые» добавляет остальные задачи; импорт такого CSV в Jira может создать новые записи. Перед применением проверьте сопоставление Issue key и Summary. Количество строк с ключом, новых и пропущенных задач показывается после выгрузки.
- Экспорт в Excel (.xlsx): выгружает все задачи в таблицу Excel и добавляет готовые сводные листы , по разделам, по статусам и по релизам. Удобно собрать отчет, посчитать что-то по-своему или отправить файл тем, кто привык работать в Excel.
- Файл «для просмотра» (read-only): самодостаточный HTML только для чтения. Внутренние задачи и поля всегда исключаются, имена исполнителей всегда заменяются псевдонимами. Это обязательная защита, ее нельзя выключить профилем. Настраиваются состав секций и штамп; настройки можно сохранить как именованный профиль (до 10 профилей), последний выбранный подставляется при следующей выгрузке.
- История версий файла: до 20 точек возврата текущего проекта хранятся в IndexedDB браузера и включаются в рабочий HTML при сохранении. В обычный JSON они не входят. Для отдельного переноса, в том числе из прежней версии, откройте Данные → Сохранение и восстановление → Дополнительные действия → «Экспорт точек»; загрузка выполняется там же кнопкой «Импорт точек». Файл истории имеет имя `versions_roadmap_ГГГГ-ММ-ДД.json`; сначала откройте нужный рабочий проект, затем импортируйте его точки и сохраните рабочий HTML. Дубли пропускаются, действует общий лимит 20 точек; проверьте сообщение о добавленных и пропущенных записях. Метку или комментарий точки можно изменить кнопкой-карандашом. Базовый план для сравнения план-факт, в отличие от этой истории, входит также в обычный JSON.
- История правок: журнал изменений (кто и когда что поменял) выгружается в CSV, с фильтром по автору и периоду.
- Замок от случайных правок: задать или снять пароль на изменения. Когда включено, любые изменения заблокированы , включая быстрое добавление задач, перетаскивание и перестановку, массовые операции, , а правки и сохранение в файл требуют ввода пароля. Это защита от случайных правок, а не шифрование данных; для настоящей защиты используйте «Экспорт JSON (зашифрованный)».

Кнопка-дискета сохраняет рабочий HTML. То же действие доступно в
«Данные → Сохранение и восстановление → Сохранить рабочий файл».
Желтая точка показывает правки,
которые еще не вошли в файл. Перед переносом нажмите сохранение и дождитесь
подтверждения. Если браузер скачивает копию, исходный файл не меняется.

Прежняя привязка JSON и его автосохранение доступны в «Сохранении и
восстановлении» как дополнительный вариант. Они не обновляют рабочий HTML:
перед переносом одного файла сохраните HTML отдельно.

При повторном импорте Jira сохраненные удаления и архив не возвращаются
в активный план. Архивные задачи могут обновляться внутри архива. Импорт
показывает пропущенные записи до применения. Для удалений из прежних версий,
где Jira-ключ не сохранился, это правило нельзя восстановить задним числом.
Если задача уже вернулась в активный план, приложение не удаляет ее автоматически.

Адрес Jira сохраняется в рабочем HTML без паролей и токенов. Ранее потерянный
адрес нужно указать один раз в «Настройки → Основное» и сохранить файл снова.
Сжатие HTML уменьшает размер без удаления плана и истории; шифрование PIN
сохраняется. Нужен браузер с CompressionStream и DecompressionStream.
Ошибка черновика вызывает уведомление один раз за период сбоя, а не при
каждой правке. Предупреждение о несохраненных изменениях остается до успеха.

### Защищенные копии

В рабочем приложении откройте «Данные → Поделиться → Дополнительно» и выберите
пакет защищенных файлов. Это встроенный
инструмент для подготовки четырех зашифрованных HTML-файлов. Он не заменяет
сохранение рабочего HTML с историей или резервную копию прежнего JSON.

1. Выберите источник: текущий план и нужный набор Презентации либо три файла,
   HTML приложения, JSON плана и HTML презентации. В первом случае заранее
   проверьте состав выбранного набора Презентации; во втором дождитесь чтения
   всех файлов. При ошибке выберите файл заново: старое содержимое не используется.
2. Создайте четыре разных пароля по 20 символов. Инструмент генерирует их
   автоматически, для каждого выходного HTML свой пароль.
3. Укажите HTTPS-адрес папки будущего размещения, без параметров, фрагмента
   или пароля в адресе. Соберите и сохраните четыре HTML-файла и `roadmap-package-manifest.json`
   с контрольными суммами SHA-256. Каждый HTML зашифрован AES-GCM, манифест
   не содержит пароли. Проверьте открытие файлов с соответствующими паролями.
4. После подготовки пакета скопируйте сообщение с паролями для чата или
   скачайте локальный TXT. Храните TXT вне публичного репозитория и папки
   размещения. Не добавляйте пароли в Git, манифест, описание релиза или исходники.
5. Если публикация разрешена владельцем данных, передайте для размещения
   только зашифрованные HTML и манифест. Пароли отправьте получателям отдельно.
   Не публикуйте исходный JSON, незашифрованную презентацию или TXT с паролями.

| Файл | Назначение |
| --- | --- |
| `roadmap-mpv0.html` | Показ выбранной Презентации или загруженного HTML презентации. |
| `roadmap-online.html` | Основная копия плана для просмотра. |
| `roadmap-online-r.html` | Копия с возможностью редактирования после открытия. |
| `roadmap-online-n.html` | Копия без редактирования. |

На экране открытия новых копий указано, что это за файл: презентация, просмотр
или редактирование. Там же находятся версия и дата выпуска Roadmap, дата
создания копии по московскому времени и визитка автора с почтой, без кнопки
покупки. Фото работает без интернета. Эти даты не являются сроками задач.
Для старых приложений без сведений о версии неизвестные значения не подставляются.
Ранее созданные защищенные HTML не меняются автоматически.

Три копии плана содержат полный переданный снимок, включая архив и внутренние
поля. Режим просмотра запрещает правки, но не обезличивает данные.
Если изменить источник, набор или пароли следующего черновика, ниже останется
предыдущий подготовленный пакет с его ссылками, паролями и повторным сохранением.
До новой сборки или закрытия окна сохраните его TXT, если он еще нужен.
Если сохранение в папку прервалось, не публикуйте частичный набор: сохраните
TXT и повторите сохранение всего пакета.

Папка `private/` в публичном репозитории не является закрытым хранилищем:
адрес, имена и размеры файлов доступны всем. Содержимое защищает шифрование,
а не название папки. Создание локальных файлов не отправляет их в GitHub
и не обновляет сайт. Размещение и проверка опубликованных ссылок выполняются
отдельно. Прежний `Локер-роадмапов.html` сохранен для совместимости;
рабочее приложение и этот порядок от него не зависят.

### Архив задач

- Откройте Архив кнопкой в шапке. Поиск фильтрует архив, очистка поля возвращает список; само открытие и поиск не восстанавливают задачи.
- Карточка явно помечена как архивная. Кнопка «Сохранить в архиве» меняет только эту запись и не возвращает ее в активный план.
- «Восстановить в план» является отдельным действием с подтверждением. Сначала сохраните несохраненные поля карточки. Конфликтующие ID и Jira-ключи остаются в архиве; результат сообщает число пропущенных записей.
- При восстановлении возвращается сохраненный путь секции. Уже существующие секции, их настройки и текущая иерархия не заменяются старыми значениями.
- «Удалить из архива» удаляет только открытую архивную запись, не активную задачу с совпавшим ID. Доступна отмена. При ошибке сохранения исходная запись возвращается.

### Сравнение версий

Сравнение показывает изменения сохраненных полей задачи, вложенных значений,
данных проекта и относительного порядка общих задач. Добавление новой задачи
само по себе не считается перестановкой остальных. Время создания снимка не
сравнивается как содержимое проекта. Длинный список различий раскрывается
командой «Показать остальные изменения» и доступен для копирования текстом.

## 10. Отчет, аудит, снимок

В разделе «Встреча» выберите «План». Здесь есть две вкладки: «Содержание» для выбора групп и задач,
названий для показа и настройки шапки, «Просмотр» для полноширинного показа.
Выбор набора и экспорт доступны в обеих вкладках. Переключатель «Изменять даты»
включает правку дат основной задачи; без него просмотр не переносит сроки.
Шапка HTML/PDF настраивается отдельно для каждого набора.

- «Прогноз срока» и «Собрать план» сначала показывают критичные ошибки. Кнопка «Показать ошибки» открывает общую очередь без старого поискового фильтра. Если ошибок нет, но не хватает данных, показано какие поля заполнить. Независимым задачам не нужно добавлять зависимости только ради завершения шага мастера.
- HTML/PDF из «Встреча → План» сохраняет выбранные названия, статусы и способ показа «Дата». Длинный текст переносится. Если в наборе есть внутренние задачи, требуется отдельное подтверждение их выгрузки. Презентация может содержать владельца и показатели всего плана из настраиваемой шапки; это не обезличенная копия.
- «Скачать для просмотра» исключает внутренние, скрытые и невыбранные задачи, а также связанные с ними контрольные даты. Общие ручные даты сохраняются. Перед передачей проверьте выбранные секции, шапку и содержание файла.

- Отчет за период («Встреча → Итоги периода»): текст для руководителя , что сделали, что в работе, что требует эскалации, что на следующей неделе. Задачи без дат не пропадают , они учитываются по статусу, а задача, у которой указан только старт, не попадает в эскалацию с нулевой просрочкой. Можно сузить охват: выбрать конкретные секции и одного исполнителя , отчет соберется только по ним. Строки можно сгруппировать по исполнителю или по роли. Копируется как обычный текст или Markdown.
- Прогресс по релизам («Встреча → Итоги периода → Прогресс по релизам»): доля выполненных задач по каждому релизу (Fix Version) с баром, датой и разбивкой готово / в работе / на холде, плюс прогноз готовности по текущему темпу. Счетчики кликабельные, нажатие раскрывает список задач этого статуса, клик по задаче открывает ее карточку. Кнопка «Скопировать как текст» собирает сводку.
- Материалы для руководства находятся в «Встреча». Сначала выберите содержание: «Статус», «План» или «Итоги периода». Затем используйте основные действия или раскройте «Другие форматы и выгрузка»: конструктор отчета, обзор всего плана, слайд, резервы времени, PNG и XLSX. Состав дополнительных форматов зависит от выбранного содержания. Кнопка «Материалы» в шапке открывает «Статус» в этом же разделе, а не отдельный центр отчетов.
  - Сводка на один лист: документ для печати или сохранения в PDF, собирается конструктором из блоков со своими текстами и профилями отчета. У сводки настраивается охват , выбор секций и одного исполнителя, , а строки можно сгруппировать по исполнителю или по роли. Есть встроенный шаблон «Маркетинг» , готовый набор блоков под маркетинговую сводку, его можно взять за основу. Документ оформлен с брендовой шапкой, KPI-карточками (готовность, выполнено, в работе, требует внимания) и аккуратными таблицами с итогами. Брендинг: к сводке можно добавить логотип (PNG, JPG или SVG до 300 КБ) и гриф («Черновик», «Конфиденциально», «Для внутреннего использования»); дата и гриф выводятся в колонтитуле, это переключается. Логотип общий для всех профилей отчета. Галочка «Финансы: бюджет и стоимость» добавляет в документ стоимость по релизам с бюджетом и дельтой и этапы с суммами актов; блок по умолчанию выключен, для внешних документов его лучше не включать. В сводку не попадают скрытые задачи, а строка с продакт-оунером не печатается, если он не указан. Если базовых планов еще нет, в отчете отклонений появится кнопка «Сохранить текущий план как базовый» , базовый план создается одним нажатием.
  - Презентация-слайды: набор слайдов формата 16:9 (обложка, прогресс по релизам, цели, риски), который печатается в PDF , готовая короткая презентация для встречи с руководством без ручной сборки в PowerPoint.
  - Картинка-слайд и одна страница PDF: компактные варианты на один экран , быстро отправить в мессенджер или вложить в письмо.
- Деньги: у задачи есть поле «Фикс. стоимость, руб» , если оно заполнено, стоимость задачи берется из него, а не из расчета по ставкам (удобно для подрядных работ и договорных сумм). Рядом выбирается статья расходов: «CAPEX / OPEX / Без статьи». В окне «Деньги» и в финансовом блоке сводки появилась строка «в том числе CAPEX / OPEX / без статьи» , видно структуру затрат.
- Аудит эпиков (Сроки → Прогноз → Другие варианты решения → Проверить эпики Jira): здоровье эпиков , возраст, статусы, наличие метрики/WSJF/влияния/описания/типа, просрочки, фокусные инициативы (метка `key_initiative`), алерты. Сверху окна , чипы-вердикты «Всего / В порядке / Есть пробелы / Проблемы», клик по чипу фильтрует список; ниже , карточки эпиков с результатами проверок и подсветкой просрочки. Считаются только загруженные сейчас проекты (это видно в подзаголовке окна). Проверка понимает русские статусы из карточки эпика, поэтому верно отличает закрытые эпики от открытых. В сводке показаны только реальные пробелы (пустые скрыты); в файле «для просмотра», где детали эпика скрыты, окно показывает пометку об этом, а не выдает скрытые поля за пробелы. Если загружен один проект (одна команда), окно упрощается: убираются выбор команды и сводный скоринг по командам, остаются статистика, алерты и таблица эпиков. Когда проектов несколько, появляется группировка по командам , она настраивается простой таблицей «проект , команда» по кнопке «Команды» (хранится у вас, в файл не попадает).
- Готовность по разделам и сигналы теперь живут плитками в виде «Сводка» (включаются кнопкой «Плитки»); подробный разбор открывается из плитки «Сигналы». Прежнее окно одного взгляда на проект. Оно объединило два прежних окна , «Инсайты» и «Сводку по секциям», теперь это две вкладки одного окна.
  - Вкладка с сигналами и готовностью: показывает, как идут дела по плану и насколько проект готов , что в работе, что просрочено, где риск не успеть к датам. Удобно понять состояние плана, не открывая отдельные отчеты.
  - Вкладка «По разделам»: весь файл на одном экране. По каждому разделу сразу видно светофор (зеленый/желтый/красный по состоянию), процент готовности, число задач, бюджет, ближайшую веху и ответственного. Удобно показать состояние всего плана руководству, не листая таймлайн.
- PNG-снимок: сохраняет видимую часть таймлайна как картинку. В снимок добавляется сводка: прогресс проекта, счетчики по статусам, просрочка, блокеры, вехи, активные фильтры и ближайшая отсечка. Перед снимком подвиньте таймлайн в нужное место. В настройках PNG-среза и печати есть галочка компактного обзорного вида , на картинке остаются только секции и вехи.

## 11. Цели и инициативы

- Для чего: связать ежедневные задачи с тем, ради чего вы их делаете. Сверху , цели (куда идем), под ними , инициативы (крупные направления работы), а к инициативам уже привязываются задачи. Так на любой задаче видно, на какую стратегию она работает, а на цели , что для нее уже делается.
- Где открыть: Инструменты → Дополнительные инструменты → Стратегия → Цели. Нужна включенная функция «Цели и инициативы».
- Измеримые исходы у цели (OKR): у цели можно задать, что считаем успехом , базовое значение, целевое, единицу измерения, , и отмечать замеры. Окно само покажет динамику и процент достижения, видно, приближаетесь вы к цели или нет.
- Вкладка «Сейчас / Скоро / Потом»: доска инициатив по горизонтам , что делаем сейчас, что на очереди и что отложено на потом. Это разговор о направлении и приоритете без жестких дат, удобно обсуждать с командой и руководством. Раньше это был отдельный вид, теперь он стал вкладкой внутри окна «Цели и инициативы».
- В карточке задачи есть поле «Инициатива» , так задача попадает в нужное направление. В дашборде виден счетчик задач, которые еще не привязаны ни к одной цели, , легко найти и подцепить «бесхозную» работу.

## 12. Риски

- Что это: единый реестр того, что может помешать плану. Раньше окно называлось непонятной аббревиатурой, теперь это понятное «Риски». В нем хранятся риски, допущения, проблемы и зависимости , каждый со своей серьезностью и статусом.
- Где открыть: Инструменты → Дополнительные инструменты → Стратегия → Риски. Нужны включенные функции «Цели и инициативы» и «Риски». Если кнопка или вкладка недоступна, проверьте их в Настройках.
- Как пользоваться: заведите запись, укажите тип (риск, допущение, проблема или зависимость), серьезность и статус. Список можно отсортировать и отфильтровать, чтобы сначала разобраться с самым важным.
- Радар: наглядная картинка, где собраны записи по серьезности , видно, что требует внимания в первую очередь, без чтения всей таблицы. Самые острые риски можно вынести на слайд «Презентации для руководства».

## 13. Рабочие режимы

Меню «Инструменты» в правой части шапки содержит два дополнительных режима:

- «Планирование»: полный рабочий набор видов и проверок.
- «Руководство»: сводка, прогноз и материалы для встречи. При переходе в этот режим активные фильтры сбрасываются, чтобы показать весь план; приложение сообщает об этом.

Режимы меняют показ, но не даты и статусы задач. Прежний режим «Моя неделя» удален; сохраненный выбор этого режима открывает «Планирование». Дополнительные возможности подключаются через «Инструменты → Подключить функции». Ненужные поля можно скрыть в Настройки → Функции без удаления значений. Для презентации без всплывающих подсказок есть отдельная настройка тихого режима.

## 14. Поиск и горячие клавиши

- На телефоне в нижней панели четыре вкладки: «Список», «Доска», «Сроки», «Встреча», как на компьютере. «Прогноз» и «Сводка» открываются внутри «Сроков», а материалы и показ плана находятся во «Встрече». Полные названия кнопок доступны для средств чтения с экрана.
- Поиск находится в шапке и ищет задачи, секции и исполнителей. `Cmd/Ctrl + F` переводит в него фокус. Enter открывает карточку, Shift+Enter показывает строку на плане.
- `Cmd/Ctrl + K` или `/` вне текстового поля открывает палитру команд. В открытом диалоге эти сочетания не перехватывают поиск.
- `Cmd/Ctrl + N` создает задачу, `Cmd/Ctrl + S` сохраняет файл, `Cmd/Ctrl + ,` открывает Настройки. Команды изменения недоступны в режиме только для просмотра.
- Отмена (`Cmd/Ctrl + Z`) возвращает не только перетаскивание и удаление, но и правки карточки задачи, а также название карты и автора, если они изменились после импорта.
- `Cmd/Ctrl + Shift + Z` повторяет отмененное действие. На Windows также работает `Ctrl + Y`.
- `Esc` закрывает верхнее открытое окно.

## 15. Безопасность данных

- JSON проходит безопасный разбор и проверку структуры перед применением. Если отдельное значение локального хранилища не читается, для него используется резервное значение; это не означает восстановление потерянных данных. Храните сохраненный рабочий HTML и резервные копии вне браузера. Дополнительный JSON не заменяет HTML с историей.
- Импортированные значения экранируются перед выводом, включая окно «Аудит Epic».

### Как обновить приложение без потери данных

Если вы уже работаете в переносимом HTML v17.0 или новее, сначала сохраните его через
«Данные → Сохранение и восстановление». Оставьте эту копию для возврата.
Для обновления кода передайте сохраненный HTML разработчику: служебный
инструмент извлечет план и историю, не запуская код возвращенного файла,
и создаст новый HTML. После открытия сравните задачи, архив и точки возврата.
Не заменяйте личный файл чистым HTML из комплекта: в нем нет вашего плана.

Переход с прежних версий, где данные хранились в JSON:

1. В старой версии откройте Данные → Сохранение и восстановление → «Сохранить сейчас». Дождитесь успешного сохранения. Затем в Данные → Резервные копии выберите «Скачать копию с датой» и проверьте, что JSON появился в папке загрузок. Храните эту резервную копию отдельно от подключенного рабочего файла.
2. До замены HTML, смены браузера или очистки его данных сохраните историю: Данные → Сохранение и восстановление → Дополнительные действия → «Экспорт точек». Проверьте файл `versions_roadmap_ГГГГ-ММ-ДД.json`. Если точек еще нет, экспортировать нечего. Рабочий JSON не заменяет этот файл истории.
3. Сохраните прежний HTML для возврата и закройте старую вкладку. Распакуйте новый локальный или полный комплект в отдельную папку и откройте его `roadmap.html`, не публичный `app.html`. Не заменяйте свой JSON файлами из комплекта и не выбирайте очистку проекта ради обновления.
4. На старте выберите «Импортировать данные» → «Импорт JSON-копии» и загрузите сохраненную резервную копию. Этот способ не подключает исходный файл к автосохранению. Проверьте название проекта, задачи, статусы, даты, Архив и базовый план. Не полагайтесь на автоматический перенос настроек и доступа к файлам между браузерами или путями HTML.
5. В открытом рабочем проекте проверьте точки возврата. Если их нет или нужна сохраненная история, выберите Данные → Сохранение и восстановление → Дополнительные действия → «Импорт точек» и укажите файл истории. Проверьте результат, включая пропуски из-за лимита 20 точек. Сам импорт точек не заменяет текущий план старым снимком.
6. После проверки сохраните рабочий HTML через «Данные → Сохранение и восстановление». В нем будут план и импортированные точки возврата. Если браузер скачивает копию, переносите файл из загрузок. Не удаляйте прежний HTML и резервные копии до успешной проверки новой версии.
