# Проверка публичной сборки

`verify-public.mjs` — единый privacy/demo/manifest gate для локального запуска и
GitHub Actions. У скрипта нет npm-зависимостей: нужен только Node.js 20 или новее.

```bash
node .quality/verify-public.mjs
```

Проверяются:

- закрытый список файлов сайта, медиа, схемы и служебных файлов GitHub;
  произвольно названные CSV, JSON, TXT и другие лишние файлы не допускаются;
- только обычные файлы, без символических ссылок;
- отсутствие рабочего `roadmap-data*.json` вне папки схем;
- отсутствие известных рабочих маркеров `RHEAD-`, `WEBADM-`, `rambler-co.ru` в
  открытых текстовых файлах;
- шифрование всех файлов в `private/`, кроме страницы-индекса;
- в `private/` допустимы только индекс, четыре контейнера с известными именами
  и необязательный для старых комплектов `roadmap-package-manifest.json`;
  при наличии манифеста обязательны `ready: true`, точный состав, SHA-256
  и размеры всех четырех файлов, без дополнительных полей с данными;
- `noindex` у закрытого раздела;
- SHA-256, размеры и подключения видео, постера и 86 скриншотов;
- пары светлой и тёмной темы для каждой функции;
- базовая структура HTML и валидность JSON-манифестов/схемы;
- отсутствие прежних `demo.mp4` и `demo.webm`.
- отсутствие устаревшего `features.png` и ссылок на него.

Если меняется видео или скриншот, сначала обновляется соответствующий манифест.
Ослаблять проверку под неподготовленный файл нельзя: публичный артефакт сначала
обезличивается, затем получает новый hash.

При добавлении новой функции каталога или служебного файла сначала обновите
явный список в проверке и регрессионные тесты. Само попадание в допустимый путь
не обезличивает содержимое: рабочие данные и пароли в этих файлах запрещены.

## Локальная работа без выпуска

`--inventory-for=X.Y` проверяет только разрешённые имена и типы файлов для
выбранного кандидата (пакет может ещё отсутствовать). Это быстрый диагностический
режим для `release:doctor`: он не проверяет содержимое и не заменяет строгую
проверку сайта.

Из папки `roadmap/` полного проекта: `npm --prefix ../_Служебное run release:bump -- --next --check`.
Команда показывает следующий номер без записи. Изменение метаданных — отдельный
шаг подготовки релиза. В отдельной копии сайта команда недоступна.
Новые номера имеют вид `X.Y`, где `Y` — одна цифра.

`node .quality/verify-public.mjs --local` проверяет сайт и неизменность
ранее опубликованного подписанного пакета по зафиксированному SHA-256.
Это не релизная приемка: соответствие пакета измененному `app.html`
не подтверждается. Неизвестный или измененный пакет отклоняется.
Без `--local` сохраняется строгая проверка точного соответствия пакета
и приложения; для выпуска и CI использовать именно ее.
