# Roadmap

План продукта в одном HTML-файле: задачи и статусы, сроки, зависимости,
команда, прогноз и материалы для руководства. Рабочая версия открывается
в браузере без отдельного сервера.

**v16.3.0 от 19.09.2026**, новый выпуск после v16.0.1.
Для публичного релиза предназначен только демонстрационный комплект.
Локальный рабочий и полный комплекты
остаются у владельца проекта и передаются отдельно.
Результаты проверки файлов находятся в `QUALITY_REPORT.md`, `validation.json`
и контрольных суммах релизных комплектов. Статус размещения сайта и архивов
проверяется отдельно от локальной сборки.

## Быстрый старт

**Посмотреть возможности:** откройте [демо](https://uchvru.github.io/roadmap/app.html).
Оно использует вымышленный проект и не предназначено для хранения вашего плана.
На [странице проекта](https://uchvru.github.io/roadmap/) доступны видеообзор без звука
и переход к каталогу.

**Работать со своим планом:**

1. Получите у владельца проекта рабочий `Roadmap-v16.3.0-local.zip`
   или полный `Roadmap-v16.3.0.zip`. Эти два комплекта не публикуются в GitHub.
2. Распакуйте полученный архив в отдельную папку. Публичный ZIP с демонстрацией
   не заменяет рабочий комплект.
3. Откройте рабочий `roadmap.html`. На старте создайте пустой план, импортируйте
   задачи или выберите «Первый рабочий план». Учебные сценарии доступны отдельно.
4. Сохраните свой план в отдельный JSON и настройте рабочее сохранение по
   [инструкции](Инструкция_Roadmap.md).

Node.js и сборочные инструменты для работы с готовым HTML не нужны.
Перед обновлением существующего плана выполните
[безопасное обновление](Инструкция_Roadmap.md#safe-update):
сохраните JSON, отдельно экспортируйте точки возврата и проверьте новый HTML.
Обычный JSON не содержит историю версий браузера.

## Какой комплект выбрать

| Комплект | Содержимое | Размещение |
| --- | --- | --- |
| `Roadmap-v16.3.0-local.zip` | Рабочий `roadmap.html`, локер, инструкция и отчеты проверки. Без сайта и медиа. | Только у владельца |
| `Roadmap-v16.3.0-public.zip` | Папка `public/`: сайт, демоприложение, каталог, медиа и инструкция. Без рабочего HTML. | Для публичного релиза |
| `Roadmap-v16.3.0.zip` | Оба комплекта, описания и контрольные суммы. | Только у владельца |

Для [страницы выпусков](https://github.com/uchvru/roadmap/releases)
предназначены только `Roadmap-v16.3.0-public.zip` и его контрольная сумма
`Roadmap-v16.3.0-public.zip.sha256`. Локальный и полный ZIP остаются локально.
Стандартный GitHub `Source code (zip)` содержит публичный репозиторий
и не заменяет рабочий комплект.

## Что находится в этом репозитории

Это публичный репозиторий [uchvru/roadmap](https://github.com/uchvru/roadmap),
основная ветка `main`. Содержимое сайта размещается через GitHub Pages.

| Путь | Назначение |
| --- | --- |
| [index.html](index.html) | Страница проекта и видеообзор. |
| [app.html](app.html) | Публичная демонстрация на синтетических данных. |
| [catalog.html](catalog.html) | Каталог возможностей со снимками интерфейса. |
| [Инструкция_Roadmap.md](Инструкция_Roadmap.md) | Пользовательская инструкция и история изменений. |
| [Локер-роадмапов.html](Локер-роадмапов.html) | Прежний отдельный инструмент для совместимости; не требуется встроенным «Защищенным копиям». |
| `catalog-img/`, `media/` | Демонстрационные изображения, видео и манифесты их версий. |
| [schemas/roadmap-data.schema.json](schemas/roadmap-data.schema.json) | Схема файла данных. |
| `.quality/`, `.github/workflows/` | Проверки состава публичной версии. |

Рабочий `roadmap.html` и служебный проект разработки не входят в дерево этого
репозитория. Рабочий HTML распространяется в локальном и полном релизных
комплектах. Клонирование репозитория или скачивание стандартного GitHub
`Source code (zip)` не заменяет локальный комплект.

## Основные возможности

- Один план в Сводке, Списке с Гантом, Доске, прогнозе «Успеваем?» и Презентации.
- Иерархия инициатив, эпиков, историй, задач, ошибок и подзадач.
- Исходные статусы Jira, настраиваемая финальность, импорт с предпросмотром.
- Сроки, спринты, релизы, зависимости и проверка последствий изменений.
- Команда, загрузка, производственный календарь, оценки и расчеты затрат.
- Архив задач, версии плана, сравнение снимков и восстановление.
- Презентация с вкладками «Содержание» и «Просмотр», отчеты и копии для показа.
- Встроенные «Защищенные копии» в меню «Данные»: четыре зашифрованных HTML-файла
  из текущего плана и выбранной Презентации либо из трех входных файлов.
- Три темы: Портал, Студия и Темная. Тема не меняет функции и данные.

[Каталог](https://uchvru.github.io/roadmap/catalog.html) описывает 43 возможности.
Версия изображений и видео указана в соответствующих манифестах; наличие нового
номера README само по себе не означает пересъемку медиа.

## Изменения v16.3.0

Это отдельный выпуск после v16.0.1. По запросу владельца удален только
режим «Моя неделя»; прежний выбор открывает «Планирование».

Изменения от 19.09.2026:

- Студия включена по умолчанию, явно выбранная тема сохраняется.
- Все возможности доступны без переключателя Простой/Продвинутый.
  В Настройки → Функции можно скрыть отдельные поля, не удаляя значения.
- Цветные подписи различают типы работ. На Доске нет повторного выбора
  статуса в каждой карточке; перетаскивание и редактор задачи сохранены.
- Легенда и карта связей упрощены; доступны и с мобильной панели таймлайна.
- Прогноз разделяет контрольные даты и цели, показывает риски целей и
  не выдает заполненные поля за гарантию корректного расчета.
- Материалы открываются из шапки, XLSX находится в «Данных», практические
  подсказки и клавиши собраны в нижней части справки.
- Мягкие градиенты кнопок и фона не меняют размеры, функции и смысловые цвета.
  Выбранные состояния и клавиатурный фокус остаются различимыми во всех темах.
- Невыбранные статусы показываются без общей прозрачности;
  усилен контраст счетчика Архива и подписи кнопки обучения.
- Нулевые статусы скрыты в полосе фильтров, пустые столбцы Доски скрыты
  по умолчанию. Их можно вернуть кнопкой «Показать пустые»; сами статусы
  остаются в справочнике и редакторе задачи.
- В справке шесть новых плиток с короткими описаниями: порядок меняется только
  при открытии, во время чтения остается стабильным. Старые выпуски в истории.
- На сайте переписаны описания, исправлены текстовые метки и упрощен каталог.
  Исторические оценки явно отделены от реальных исследований пользователей.
- Кнопка «Хочу купить» на сайте открывает форму письма автору. Она готовит
  письмо на `uchv@ya.ru` в почтовом приложении посетителя, но не отправляет
  его автоматически. Можно отдельно скопировать текст письма.

- Сохранение сравнивает содержимое снимков точно: совпадение короткого хеша
  больше не может скрыть изменение плана.
- Старые записи истории проходят проверку принадлежности проекту до применения.
- «Защищенные копии» работают внутри приложения без отдельного локера.
  Инструмент создает четыре разных пароля по 20 символов, сообщение для чата
  и локальный TXT с паролями после подготовки файлов. Правка следующего
  черновика не удаляет ссылки и пароли предыдущего пакета. Сборка не использует
  прежний файл при повторном выборе, ошибке чтения или до завершения загрузки.
- Каскадный порядок учитывает направление зависимостей и одинаковые ID,
  записанные числом или строкой. Обход больших графов выполняет меньше лишней работы.
- Пустой охват отчета не превращается в весь план; посторонние секции не
  добавляются в выбранный набор. Финальность эпика в отчете за период берется
  из настроек статусов, включая собственные статусы проекта.
- Импорт сохраняет названия статусов исходных CSV;
  отсутствующие категории не угадываются.
  «Открытый» распознается как группа «В плане», без переименования исходного статуса.
- Фильтры статусов упорядочены по числу задач: «Все» первым, затем по убыванию;
  равные счетчики сохраняют порядок. Справочник и столбцы Доски не переставляются.
- Карточки изменений в справке получили адаптивную сетку и мягкие цветовые акценты.
- Виртуализация обновляет стили только изменившихся пар строк. Все задачи остаются в документе.
- Проверка производительности отклоняет отсутствующие и некорректные измерения.
- В сборке 19.09.2026 кнопки стартового окна вынесены в отдельную область:
  они не перекрывают заголовок и пояснение на средней и узкой ширине.
- Выбранные вкладки рабочих экранов используют общую палитру темы;
  усилен контраст текста невыбранных вкладок в светлой теме.
- Браузерные проверки не повторяют упавшие сценарии автоматически;
  клавиатурный обход учитывает переход фокуса через панель браузера.
- Итоговый ответ прогноза выделен в отдельный проверяемый модуль. Подписи,
  расчеты и автономный запуск одного HTML сохранены.
- Служебный валидатор и предпросмотр исправлений используют общие правила
  финальных и приостановленных статусов, согласованные с приложением.
  Предпросмотр не изменяет план автоматически.

Исправления v16.0 и v16.0.1 для статусов Jira, архива, адаптивных строк,
клавиатуры и экспорта сохранены. Результаты проверки точных файлов
зафиксированы в `QUALITY_REPORT.md` и `validation.json` внутри комплектов.
Матрица проверки включает три темы, широкие и узкие экраны, клавиатуру,
импорт, архив и защищенные копии. Отчет привязан к контрольным суммам файлов,
а не только к номеру версии.

## Данные и ограничения

Базовая работа с локальным планом доступна офлайн. Данные остаются в выбранном
JSON или в браузере; сеть используется при явном внешнем действии, например
обмене с Jira. Публичная демонстрация содержит только вымышленные данные.

Не добавляйте в репозиторий рабочий JSON, токены, пароли, настройки подключения,
историю, незашифрованные рабочие выгрузки или TXT с паролями. Текст для чата
и TXT остаются у вас; получателям передаются отдельно от файлов.

В публичной `private/` могут размещаться только разрешенные владельцем
зашифрованные HTML-контейнеры и их манифест SHA-256. Четыре копии защищены
AES-GCM, но сама папка публична: имена и размеры файлов не скрыты, адрес
не является средством защиты. Создание локального комплекта не публикует его
автоматически. Порядок описан в
[инструкции по защищенным копиям](Инструкция_Roadmap.md#protected-copies).
Ранее созданные копии остаются отдельными снимками. Публикация нового
приложения не меняет их пароли и не добавляет в них новые исправления.

Проверки выполняются на синтетических планах. Точные счетчики и соответствие
статусов конкретной Jira проверяются по исходной CSV-выгрузке. Названия,
потерянные старой версией при объединении статусов, нельзя достоверно восстановить
без повторного импорта.

Синтетические оценки на странице проекта не являются ответами реальных
пользователей и не подтверждают спрос или готовность внедрения.
